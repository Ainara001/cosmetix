# Структура каталога, SQLite v16

Версия БД: **16** (было 15). Миграция только добавляет таблицы. Существующие `products`, их `id`, цены, корзина, избранное, заказы, `products.shade` и `product_shades` не меняются.

## Модель

```
бренд → линейка (product_lines)
          └─ вариант = существующая строка products (01, 02 ...: своя цена, корзина, избранное)
               ├─ product_shades            (v15: тип, код и имя варианта, оценка цвета)
               ├─ product_variant_facts     (v16: число ячеек, источник, дата, достоверность)
               └─ product_shade_pans        (v16: отдельные ячейки палетки)
```

Одна палетка = один покупаемый товар (строка `products`). Номер варианта (01, 02) и цвет ячейки внутри палетки — разные сущности: первый хранится в `product_shades.shade_code`, второй в `product_shade_pans`.

| Таблица | Что хранит |
|---|---|
| `product_lines` | ключ линейки (тот же, что `product_shades.line_key`), `slug`, бренд, название без номера, тип, источник, дата проверки, достоверность |
| `product_variant_facts` | на ОДИН товар: `pan_count` (NULL = не установлено), источник, дата проверки, достоверность, примечание |
| `product_shade_pans` | ячейка: `pan_key` (стабильный id), `product_id`, `position`, `name`, `finish`, `colour`, `colour_source`, `colour_status`, `measurement_ref` |

`pan_key` = `<slug линейки>/<код варианта>/<номер ячейки>`, например `romand-better-than-palette/02/07`. Он не зависит ни от порядка строк, ни от `products.id`, поэтому будущие измерения не потеряются.

## Правила

- **Ячейки создаются только там, где источник подтверждает их число.** Сейчас это 6 палеток Better Than Palette (00, 01, 02, 03, 05, 07) по 10 ячеек = 60 строк. У Better Than Eyes число не установлено (продавцы расходятся), ячеек нет.
- **Цвет ячейки пуст (`missing`).** Файлы каталога не умеют записывать цвет ячейки, а статус `measured_swatch` требует `measurement_ref`. Реальные цвета появятся только из наших измерений физических образцов.
- `position` — наша нумерация ячеек. Она не утверждает, что совпадает с расположением на реальной палетке, пока это не показали измерение или фото.
- Название и покрытие ячейки (`name`, `finish`) NULL, пока источник их не назвал.
- Старые оценки цвета остаются как были: у помад и румян это `legacy_estimate` в `product_shades`, у палеток общий декоративный цвет остаётся в `products.shade`, как цвет отдельной ячейки он не выдаётся.
- Повторный запуск `SeedData.applyCatalogStructure` ячейки только ДОБАВЛЯЕТ (`INSERT OR IGNORE`), поэтому записанный позже измеренный цвет не затирается.

## Достоверность фактов (`confidence`)

| Значение | Смысл |
|---|---|
| `official_page` | страница производителя, прочитанная и проверенная вручную |
| `official_page_unchecked` | страница производителя, прочитанная через инструмент и ещё не проверенная вручную |
| `third_party` | INCIDecoder, продавец |
| `unconfirmed` | источники расходятся или не найдены |

Все 6 палеток записаны как `official_page_unchecked`: число 10 взято из пересказа официальной страницы Rom&nd инструментом чтения страниц, повторная проверка 2026-11-05 была отклонена сайтом (HTTP 429). Это нужно один раз проверить вручную и поднять до `official_page`. Для 00, 03, 05, 07 в пересказе отдельно названы только 01 и 02, число для остальных взято из фразы «в каждой палетке десять оттенков». Это записано в `note`.

Линейки помад записаны как `third_party` без даты проверки (дата не фиксировалась), официальный сайт Peripera с нашей сети недоступен.

## Целостность

Ограничения самой БД: уникальность `pan_key` и `(product_id, position)`, внешние ключи с `ON DELETE CASCADE`, `CHECK` на статус, покрытие, непрозрачный ARGB-цвет, «цвет есть ⇔ статус не `missing`», «цвет требует источник», «`measured_swatch` требует `measurement_ref`».

Остальное проверяет `CatalogIntegrity.check` (`lib/database/catalog_integrity.dart`, только чтение): нет оборванных внешних ключей, `line_key` известен, число ячеек = `pan_count`, нумерация 1..N без пропусков, `pan_key` соответствует линейке, коду и номеру, ячейки есть только у товара с подтверждённым числом.
