## 1. Главный вывод

1. **Код PSGAN можно использовать:** лицензия MIT, в том числе в коммерческих продуктах.
2. **Готовые веса и вспомогательные модели из этих репозиториев для коммерческого релиза брать нельзя**, пока не решены три вопроса:
   - `lms.dat` (в репозитории PSGAN) по размеру и коду это 68-точечный предсказатель dlib. Автор модели прямо пишет, что он не может использоваться в коммерческом продукте, потому что набор iBUG 300-W исключает коммерческое применение.
   - `resnet.pth` (разбор лица) обучен на CelebAMask-HQ; у набора лицензия «только некоммерческие исследования и образование».
   - `G.pth` (сам генератор): лицензия MIT относится к репозиторию, но **данные, на которых он обучен (MT-Dataset), под какой лицензией, не установлено** ✗.
3. **PSGAN-NCNN не имеет лицензии** (`license: null` в GitHub API). По умолчанию это «все права защищены»: ни код, ни файлы моделей копировать нельзя. Использую только как идею (две стадии: расчёт gamma и beta, затем перенос).
4. **NCNN можно использовать:** BSD-3-Clause, плюс перечисленные сторонние части (zlib, BSD-2, BSD-3).
5. **Главный блокер всего проекта:** нет проверенного набора данных с разрешением на коммерческое обучение. Без него «самостоятельная реализация PSGAN» означает архитектуру по статье и обучение на данных, которые у вас есть право использовать (например, собственные съёмки с письменным согласием людей).
6. **Real Skin Makeup нельзя строить на анализе кожи Cosmetix:** он не ищет акне, рубцы и покраснения (в приложении только цветотип по селфи через Gemini), точности по ним нет. Нужна отдельная маска защиты плюс ручная правка (раздел 5).

## 4. Как сделать самостоятельную реализацию, не обходя лицензии

Принципы:
- **Не копировать и не «переписывать» чужие файлы.** Ни переименованием, ни пересборкой структуры, ни автоматическим пересказом. Для PSGAN-NCNN, где лицензии нет, даже не использовать его код как основу.
- **Источник идеи:** опубликованная статья [PSGAN, CVPR 2020, arXiv 1909.06956](https://arxiv.org/abs/1909.06956) и [PSGAN++, arXiv 2105.12324](https://arxiv.org/abs/2105.12324) (в ней предложено сохранение деталей макияжа, и это ближе к нашей задаче). Алгоритм из статьи не защищён авторским правом как код, но **патентный статус не проверял** ✗ (нужна консультация юриста перед коммерческим выпуском).
- **Код PSGAN (MIT)** допустимо читать как справочник. Если когда-либо брать из него фрагмент, нужно сохранить текст MIT и уведомление автора; уведомление zll для кода разбора лица в PSGAN отсутствует, поэтому надёжнее писать свой код по статье.
- **Свои веса:** обучить собственную сеть на данных с разрешением (собственные съёмки с письменным согласием, либо данные, лицензия которых прямо разрешает коммерческое обучение). Пока таких данных нет, **генератор переноса не может быть выпущен**.
- **Замены для запрещённых частей:**
  - ориентиры лица: MediaPipe Face Mesh V2 (Apache 2.0), уже проверен в этом проекте (478 точек, около 15 мс на CPU Mac);
  - разбор лица на зоны: нужна своя модель или классический метод по ориентирам (многоугольники зон по точкам MediaPipe); готовой разрешённой модели не нашёл ✗.

## 5. Режим Real Skin Makeup (проект)

Всё ниже это проект, а не проверенный результат. Ничего не реализовано и не измерено.

**Принцип.** GAN формирует цвет макияжа, но **итоговые пиксели кожи не берутся из выхода GAN.** Выход GAN используется только как «задание по цвету» для низких частот (тон, оттенок), а высокие частоты оригинала (поры, рубцы, края прыщей, текстура) переносятся без изменений:

`итог = оригинал + α · M_зоны · M_нет_защиты · (низкие_частоты(GAN) − низкие_частоты(оригинал))`

- `α` ползунок интенсивности (0–100%); `M_зоны` маски отдельных областей (губы, веки, брови, щёки, тон); `M_нет_защиты` обнуляет перенос в защищённых местах.
- Высокие частоты в области кожи **не меняются никогда** (нет сглаживания, нет ретуши).

**Маска защиты (прыщи, рубцы, покраснения).** Анализ кожи Cosmetix для неё непригоден: он этого не определяет. Предлагается отдельная маска:
1. Автоматическая подсказка классическими методами (локальное отклонение цвета и контраста от соседней кожи, красный канал в Lab). Точность неизвестна, нужно измерить.
2. **Ручная правка обязательна:** пользователь стирает и добавляет защищённые области пальцем.
3. Цвет под защитной маской остаётся оригинальным. Покраснение при этом **не маскируется макияжем** (так задумано: «настоящая кожа»).

**Предупреждения вместо ложной достоверности.** Если уверенность маски низкая, лицо повёрнуто, свет плохой, пятна на краю зоны и т. п., приложение показывает явное предупреждение («результат приблизительный, участки отмечены») и подсвечивает сомнительные места. Режим не должен показывать результат без такой пометки.

**Интенсивность, зоны, сравнение.** Ползунок интенсивности, переключатели по зонам и сравнение оригинала с результатом (разделитель «до / после», удержание для просмотра оригинала).

## 6. Архитектура интеграции и сравнение локально / сервер

Измерений скорости и качества **нет**, ниже только структурное сравнение.

| | Локально (NCNN) | Сервер (например, FastAPI + PyTorch) |
|---|---|---|
| Конфиденциальность | Фото не покидает телефон. Соответствует текущей политике Cosmetix (фото уходят на сервер только по согласию) | Фото уходит на сервер: нужно отдельное явное согласие, хранение и удаление |
| Размер | Модели на устройстве. Ориентир: `G.pth` 50,5 МБ (fp32); у PSGAN-NCNN две сети по ~34 МБ и парсер ~53 МБ (fp32, **только как ориентир размера, файлы не используем**) | Приложение лёгкое |
| Скорость | Зависит от телефона, **не измерено** | Зависит от GPU и сети, **не измерено** |
| Работа без сети | Да | Нет |
| Обновление модели | Через релиз приложения или загрузку | Мгновенно на сервере |
| Стоимость | Нет затрат на сервер | GPU и трафик |
| Сложность Flutter | Нужен нативный мост (FFI) или пакет `ncnn` 0.1.0; сборка под Android и iOS; Vulkan через MoltenVK на iOS | Простой HTTP-клиент, как для ИИ-чата |

**Рекомендация:** локальная обработка по умолчанию (соответствует политике фото), сервер только как необязательная опция с согласием. Решение не окончательное: до измерения времени работы на реальных Android и iPhone и размера моделей это гипотеза. Альтернативы NCNN для запуска на устройстве: ONNX Runtime (MIT) и Core ML через coremltools на iOS.

## 7. Тесты, которые нужно подготовить (до разработки)

Пороги ниже **стартовые гипотезы**, их нужно откалибровать на реальных данных.

1. **Качество переноса:** разница цвета в зонах (ΔE по Lab) между референсом и результатом; визуальный осмотр на разных тонах кожи и освещении.
2. **Сохранение несовершенств:**
   - на фото с добавленными синтетическими пятнами (известная маска) энергия высоких частот в зоне кожи после переноса должна совпадать с оригиналом (ожидание: не ниже 98%);
   - в защищённых областях цвет совпадает с оригиналом;
   - реальные примеры с акне, рубцами и покраснениями только с согласием людей.
3. **Нет сглаживания:** автоматическая проверка, что высокочастотная часть кожи неизменна; тест падает при любом сглаживании.
4. **Предупреждения:** при низкой уверенности маски, повороте лица, плохом свете предупреждение появляется.
5. **Производительность:** время работы (p50, p95), память, нагрев на нескольких реальных Android и iPhone; размер установленного приложения.
6. **Совместимость Android и iOS:** запуск на симуляторе и реальном устройстве, одинаковый результат на обеих платформах с допуском.
7. **Регрессия:** все существующие тесты Cosmetix (496 Flutter, серверные) проходят без изменений.
