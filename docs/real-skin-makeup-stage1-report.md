# Real Skin Makeup, этап 1: отчёт

Дата: 5 ноября 2026. Ветка `feature/real-skin-makeup-stage1`. Основа: `docs/psgan-license-and-integration-report.md` и
`docs/real-skin-makeup-plan.md` (актуализированы относительно `main` `d93ae7f`).

Обозначения: ✓ проверено запуском или по первоисточнику; ✱ проверено только частично; ✗ не проверено.

## 1. Что сделано

Самостоятельный модуль виртуальной примерки помады, теней и румян **без генеративной модели**:
перенос цвета по маскам зон лица, регулировка интенсивности, выбор зон, защитная маска с ручной
правкой и сравнение до и после. Фото обрабатывается на телефоне, не отправляется и не сохраняется.

| Требование | Как сделано | Статус |
|---|---|---|
| Самостоятельный модуль | Всё в `lib/features/virtual_makeup/`; тест проверяет, что модуль не импортирует базу, каталог, провайдеры, сервер и анализ кожи | ✓ |
| Цвет помады, теней, румян | `ColorTransferBackend`: сдвиг в Lab на одну и ту же величину для всей зоны | ✓ |
| Сохранение текстуры, без сглаживания | Сдвиг одинаков для всех пикселей зоны, поэтому разницы между соседними пикселями (поры, рубцы, пятна) не меняются. Размывается только **маска**, не фото. Тест: энергия мелких деталей в зоне 90–115% от исходной; на реальном фото 99,5% (губы), 100,2% (румяна), 100,0% (тени) | ✓ |
| Нет ретуши, прыщи и рубцы остаются | Тесты на синтетическом лице с красными точками, бледной линией и красным пятном: они видны и после макияжа; в коде движка нет блюра, шумоподавления и «ретуши» (проверяется тестом по тексту) | ✓ |
| Защитная маска и ручная правка | `ProtectionMask`: кисть, ластик, размер, отмена, возврат, очистка. В защищённых пикселях результат совпадает с фото **байт в байт** (тест на синтетике и на реальном фото) | ✓ |
| Автоподсказка не выдаётся за точную | `BlemishSuggester` только предлагает; ничего не защищается, пока пользователь не нажмёт «Защитить»; в интерфейсе написано, что подсказка находит лишь мелкие пятна и может ошибаться; при слишком большом охвате (больше 12%) подсказка не показывается | ✓ |
| Не выдавать результат за гарантированный | Постоянная плашка над списком (не прокручивается), предупреждения о повороте, наклоне и малом размере лица, при нескольких лицах или без лица примерка не запускается | ✓ |
| Интенсивность, зоны, до/после | Ползунок и переключатель у каждой зоны; «Результат / Оригинал / Разделитель» и удержание фото | ✓ |
| Замена движка (PSGAN и др.) | Интерфейс `MakeupBackend` с `capabilities` (поддержка референса, работа на устройстве); контракт движка описан в коде. Генеративных весов и заглушек нет | ✓ |
| Лицензии | см. раздел 3 | ✓ |
| Android и iOS | iOS: собрано и запущено на симуляторе. Android: пакет заявляет поддержку, **не собирал** (на этой машине нет Android SDK) | iOS ✓ / Android ✗ |
| Существующие функции | Изменены только: `pubspec.yaml`, `pubspec.lock`, `lib/routes/app_routes.dart` (+ маршрут), `lib/screens/profile/profile_screen.dart` (+ одна строка меню), файлы переводов EN и KK (+47 пар строк, всего 61 добавленная строка в каждом файле; удалений нет). База (версия 14), каталог, сервер, анализ кожи, возрастные ограничения не тронуты | ✓ |

## 2. Архитектура

```
lib/features/virtual_makeup/
  virtual_makeup.dart               точка входа (экспорт)
  domain/   makeup_look, face_geometry (478 точек, индексы MediaPipe), face_quality
  engine/   rgba_image, color_math (Lab), polygon_raster (маски), zone_masks,
            protection_mask, blemish_suggester, makeup_backend (интерфейс),
            color_transfer_backend (движок этапа 1)
  landmarks/ face_landmark_provider (интерфейс), mediapipe_landmark_provider (единственный файл с пакетом)
  ui/       экран, контроллер, палитры, панель маски, вид фото с до/после, плашка
```

Формула движка: `итог = оригинал + маска × (1 − защита) × интенсивность × сдвиг`, где `сдвиг` один и тот же
для всех пикселей зоны (целевой цвет минус средний цвет зоны). Пиксель с нулевым эффектом не перезаписывается
вообще, поэтому «нетронуто» означает «байт в байт».

### Вручную на симуляторе (iPhone 16)
Профиль → «Виртуальная примерка» → выбор фото из галереи → лицо найдено → смена цвета помады и интенсивности →
вкладка «Защита кожи» → мазок кистью по щеке. **Нашёл и исправил ошибку:** в режиме «Защита кожи» всё фото
заливалось голубым (цвет маски не был предумножен на прозрачность). Исправлено и закрыто тестом. Подпись
«Результат» переносилась на две строки, исправлено. После правок экран проверен снова.

После исправлений по ревью (пересобранное приложение, поверх старого, затем перезапуск процесса): фото из галереи → лицо найдено →
«Защита кожи» → быстрый мазок по щеке: нарисован целиком, «Защищено: 0.7% фото» → «Другое фото» → пейзаж без лица: **прежнее фото
осталось на экране**, сверху сообщение «Лицо не найдено». Мазок кистью по ходу движения, замена фото и возврат на главную ошибок не дали
(в консоли отладки я их не просматривал).

## 5. Что проверено где

**Только на симуляторе iPhone 16 и на тестовом движке Flutter, не на телефоне:**
- настоящий MediaPipe на портрете, время поиска лица и рендера (отладочная сборка);
- ручные сценарии: выбор фото, мазок кистью, отказ от фото без лица, плашка, подписи;
- чтение фото и поворот по EXIF (тестовый движок, не декодер телефона);
- удаление временной копии: проверена логика путей тестами и чтением плагинов, а не реальным выбором фото с физического устройства.

**Требует физического iPhone (Apple ID в Xcode):** скорость и память в релизной сборке; поведение декодера при повороте по EXIF на настоящих
снимках с камеры; выбор из галереи и съёмка камерой (разрешения); тепловой режим и поведение при долгой работе кистью.

**Требует Android-устройства или эмулятора:** всё; сборка не проводилась (нет Android SDK).

## 6. Чего НЕ подтверждено (честно)
- **Скорость и память на физическом iPhone и на Android не измерены.** Цифры выше только для симулятора в отладочной сборке: о релизе на телефоне они ничего не говорят. Замер ждёт Apple ID в Xcode.
- **Android не собирался и не запускался** (нет Android SDK). Пакет заявляет `minSdk 24`, `arm64-v8a`, `x86_64`; 32-битные ARM-телефоны не поддерживаются.
- **Автоподсказка пятен не проверена на размеченных данных.** На реальном портрете она пометила 39 областей (8,9% кожи), и я не разбирал, какие из них настоящие пятна: она может принимать за пятна поры, щетину и тени. Это подсказка, не диагностика.
- **Качество макияжа простое:** сдвиг цвета без блеска, матовости, глиттера и без настоящего «слоя» косметики. На тёмной коже тени получаются слабыми даже при 100%. Реалистичный перенос по референсной фотографии в этапе 1 **не делается** (нет моделей с подтверждёнными правами).
- Зоны проверены на двух реальных портретах и синтетическом лице; на разных освещении, возрасте, очках и бороде не проверялись. Для этого годится стенд `tools/eval` из PR #18.
- Контракт движка (нет сглаживания, защищённые пиксели байт в байт) проверен только для `ColorTransferBackend`; общий набор контрактных тестов для будущих движков ещё не выделен.
- Работа на симуляторе: подготовка зон считается заново при каждом новом фото, время первой подготовки отдельно не измерено.

## 7. Как подключить другой движок позже
Реализовать `MakeupBackend` (в `capabilities` указать `supportsReference`), принять `PreparedFace` и, при необходимости, референс;
пройти те же контрактные проверки (размер результата, защищённые пиксели байт в байт, отсутствие сглаживания).
Прав на веса PSGAN и аналогов нет, поэтому такой движок сейчас не подключается.
