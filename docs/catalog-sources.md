## 2. Страна производителя

Правило: страна пишется, только если источник **прямо** называет страну
производства («Made in …», «Country of origin», `manufacturing_places` у того же
штрихкода и той же версии товара). Страна бренда/штаб-квартиры — не страна
производства и не подставляется. У записи обязательна ссылка (`country_source`),
иначе файл не загрузится.

**Итог: ни для одного из 37 настоящих товаров подтверждённой страны не найдено,
поле пусто у всех.** На странице товара показано «Страна производителя: не
указана». Механизм готов: появится страна со ссылкой в JSON — она придёт в базу
миграцией (для уже установленных копий нужна следующая версия схемы с
`applyCountries`) и покажется со ссылкой на сайт-источник.

## 3. Единые категории при импорте из магазинов

`lib/services/catalog/category_normalizer.dart`, словарь
`assets/catalog/category_dictionary.json` (38 типов, 36 фраз).

1. Текст режется на слова (`крем-гель` — два слова), приводится к нижнему
   регистру, `ё` → `е`, числа отбрасываются.
2. Каждое слово обрезается до основы лёгким стеммером (окончания «-ый/-ая/-ов/-ами…»,
   английское множественное `s`): «кремы», «крема», «кремом» → `крем`.
3. Слова-описания из списка `ignore` («увлажняющий», «для лица», `moisturizing`…)
   на тип не влияют. Остаётся **набор** основ: порядок не важен.
   «увлажняющий крем» и «крем увлажняющий» дают один набор и один ключ.
4. Тип слова из словаря голосует за свой тип; фразы («тональный крем» = тональная
   основа, «крем SPF» = солнцезащитное средство, «бальзам для губ») весят больше,
   чем одно слово; побеждает самое длинное совпадение.
5. Один победитель → категория выбрана (`matched`). Два и больше типов с равным
   весом («крем-гель»), либо ни одного слова из словаря («бальзам», «набор кистей»)
   → категория **не угадывается**, запись попадает в очередь.

### Очередь ручной проверки (для админки)

Таблица `category_review_queue` (миграция 14), репозиторий
`lib/repositories/category_review_repository.dart`: магазин, исходный текст,
ключ формулировки, причина (`ambiguous`/`unknown`), кандидаты, подсказка ИИ,
статус. Одна формулировка одного магазина — одна строка. `toJson()` отдаёт
запись в формате для админки/сервера. Решение человека (`resolve`) запоминается,
`aliases()` подставляется в `CategoryNormalizer.load(aliases: …)`, и такая
формулировка дальше распознаётся сама.

### Роль `ProductClassifier`

`lib/services/catalog/category_import_service.dart` вызывает существующий
`ProductClassifier.classify` **только** для неоднозначных случаев и записывает
ответ как текст «ИИ (подсказка, не решение): …» в поле `ai_hint`. Выбор категории
по нему никогда не делается. Честное ограничение: классификатор отвечает «для
какой кожи и цветотипа товар», а не «какая это категория», поэтому подсказка
слабая; без сети импорт продолжается с пустой подсказкой.

В очередь пока попадает только то, что передаст в `CategoryImportService.process`
будущий импортёр: самого импорта из магазинов в приложении нет (см. раздел 4).

## 4. Можно ли пользоваться открытыми данными

### Open Beauty Facts

Источники: [terms-of-use](https://world.openbeautyfacts.org/terms-of-use),
[data](https://world.openbeautyfacts.org/data),
[документация API](https://openfoodfacts.github.io/openfoodfacts-server/api/),
`robots.txt`.

* **Лицензии:** база — ODbL; отдельные записи — DbCL; фото — CC BY-SA (на
  дизайн упаковки могут действовать права третьих лиц).
* **Обязательно:** указание авторства (текст вида «Contains data from Open Beauty
  Facts, available under the Open Database License» + ссылка на openbeautyfacts.org
  или страницу товара) в самом приложении, на видном месте.
* **Share-Alike:** если публично используется *адаптированная база*, её надо
  открыть под ODbL. Применимо ли это к одному значению «страна» у десятка товаров
  внутри каталога — юридический вопрос, **не решён**; я не юрист. Поэтому в
  каталог сейчас не взято ни одного значения из OBF.
* **Точность не гарантирована** (в условиях прямо: данные вносят добровольцы,
  возможны ошибки). Поэтому каждое значение должно иметь ссылку на карточку и
  проверяться по фото упаковки.
* **API:** лимит 15 запросов/мин на IP для чтения товара, 10 запросов/мин для
  поиска; обязательный собственный `User-Agent` вида `Приложение/версия (e-mail)`;
  просят заполнить короткую форму об использовании (**не заполнена** — это за
  вами). Для больше нескольких сотен товаров просят качать дампы (JSONL/CSV/Parquet).
  Для постоянной работы приложения у пользователей лимит считается на пользователя.
* **Противоречие:** `robots.txt` для `User-agent: *` запрещает `/api`, а
  документация приглашает пользоваться API. Я сделал ~20 запросов поиска v2 с
  паузой 8 с, с понятным `User-Agent` (без e-mail) — в рамках документированных
  лимитов. Для разового сбора достаточно; регулярный обход — через дампы.

### CosIng

Источник: [страница Европейской комиссии](https://single-market-economy.ec.europa.eu/sectors/cosmetics/cosmetic-ingredient-database_en).

* База — справочник названий (INCI) и ограничений ингредиентов. Страница сама
  пишет: «informative purpose and no legal value», не определяет допустимость
  вещества (это делает Регламент (ЕС) № 1223/2009).
* **Формат выгрузки не подтверждён**: на странице нет ссылки на скачиваемый файл,
  поиск `data.europa.eu` набора CosIng не нашёл. Упоминания CSV/XLS — из
  стороннего руководства 2018 года для веб-интерфейса, не проверены.
* **Лицензия на саму базу не подтверждена.** Общая политика сайта Комиссии:
  контент ЕС «если не указано иное» — CC BY 4.0 (нужна ссылка и пометка об
  изменениях). Распространяется ли это на CosIng, не сказано.
* Вывод: **не используется**, данных из неё в каталоге нет. Перед использованием
  надо написать в Комиссию/найти явную лицензию на набор.

### Магазины: что сказано в `robots.txt` и условиях

Ничего не собиралось; для обоих магазинов код-импортёра не написан.

**Золотое Яблоко (goldapple.kz).** `robots.txt` прочитан (`User-agent: *`):
запрещены `/catalog/product/view/`, `/catalog/category/view/`,
`/catalogsearch/`, `/checkout/`, `/customer/`, `/rest/`, `/swagger/`, любые URL
на `.html`, сортировка/фильтры; Crawl-delay не задан, есть `Sitemap`. **Пользовательское
соглашение я не нашёл и не прочитал**: в статическом HTML главной нет ссылок, а
в окне браузера приложения сайт показал «страница недоступна» (защита от
автоматических запросов; обходить её я не стал), так что подвал страницы я не
видел. Вывод: `robots.txt` страницы товаров с `.html` и поиск закрывает, условия
использования неизвестны → **не парсить** до письменного разрешения магазина или
чтения соглашения человеком.

**Диона (dionashop.kz)**: адрес взят из карточек Яндекс.Карт и 2ГИС (веб-поиск);
`dione.kz` и `dionecosmetics.kz` не существуют (DNS не находит). `robots.txt`: `Crawl-delay: 30`, закрыты `/personal/`, `/bitrix/`,
`*/order/`, `*/search/`, фильтры, сортировки, `?PAGEN` и т. п.; каталог не закрыт.
Общих условий использования сайта не найдено: на сайте есть только условия
оплаты, доставки, возврата, подарочных сертификатов и согласие на обработку
персональных данных. Отсутствие запрета ≠ разрешение, права на описания и фото
остаются у магазина. Вывод: **не парсить**; допустимо только получить
письменное разрешение или договориться о выгрузке.

Цены/наличие в приложении остаются демонстрационными (`product_prices.source =
'demo'`): открытых источников цен нет.

## 5. Пометки DEMO

Заменённых настоящими данных, ради которых можно было бы снять пометку, нет:

* цены и наличие в магазинах — по-прежнему `demo` (подпись «демо-данные», текст

  у Maison Margiela — страница Costco;
* набор Cosmetix «Нежность» выдуман: в JSON `"demo": true`, без источника;
  **в интерфейсе он пока не помечен** — отдельная правка, поведение приложения
  в этой задаче не менялось;
* страна производителя — «не указана», не DEMO и не угадана.

Итого: ни одна пометка DEMO не снята, потому что нечем подтвердить замену.

## 6. Воспроизвести

```bash
flutter pub get
flutter analyze
flutter test                      # тесты каталога: test/catalog_json_test.dart
```

Тесты читают JSON с диска через `test/flutter_test_config.dart` (без привязки
Flutter, иначе тесты ИИ с настоящим HTTP получают 400).
