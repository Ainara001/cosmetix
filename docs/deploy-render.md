# Сервер Cosmetix на Render: подготовка (ничего не создано)

Файл `render.yaml` в корне — Blueprint. **Ресурсы не созданы**, секретов в репозитории нет.
Цены и лимиты тарифов Render здесь не утверждаются: проверьте их на render.com перед
применением (бесплатный веб-сервис засыпает без трафика — первый запрос будет медленным).

## Шаги (делает владелец)

1. Репозиторий должен быть доступен Render (приватный репозиторий подключается через
   GitHub-аккаунт; публиковать код не нужно).
2. Render → New → Blueprint → выбрать репозиторий и ветку → применить `render.yaml`.
3. В панели Render ввести значения для `APP_TOKEN` (любая длинная случайная строка) и,
   если нужен ИИ, `GEMINI_API_KEY`. **Фото в Gemini не отправляются**
   (`PHOTO_ANALYSIS=off`, `GEMINI_BILLING=free`).
4. После запуска `GET https://<имя>.onrender.com/health` должен ответить `ok`; миграции
   применяются при старте (`AUTO_MIGRATE=1`).
5. Сборка приложения с адресом сервера:
   `flutter build ios --simulator --dart-define=AI_BASE_URL=https://<имя>.onrender.com --dart-define=AI_APP_TOKEN=<токен>`
   (без `AI_BASE_URL` приложение не делает сетевых запросов).

## Каталог и цены

* Первичное наполнение каталога: `node db/cli.js seed` (из `server/`, с `DATABASE_URL` базы
  Render — внешняя строка подключения из панели Render).
* Админ-панель по умолчанию **только локальная** (см. `server/README.md`). Реальные
  предложения магазинов вводят локально: `DATABASE_URL=<внешняя строка Render> npm start`
  в `server/`, затем `http://localhost:8787/admin` — запись пойдёт в базу Render, а
  приложение получит её через `GET /v1/catalog/offers`.
* Админ-аккаунт: `ADMIN_PASSWORD=... node db/cli.js create-admin <имя>` (пароль 12+
  символов, в репозиторий не попадает).

## Не сделано / риски

* Не проверено на реальном Render (аккаунта и ресурсов нет; платежи не подключались).
* Бесплатная база и веб-сервис могут иметь ограничения по сроку и объёму: проверьте до
  использования для реальных пользователей.
* Согласие и политика конфиденциальности для передачи профиля и событий на сервер ещё не
  оформлены, поэтому эти маршруты в приложении не подключены (см. PR #27–#34).
