# Клиент сервера Cosmetix (сервисный слой)

Код: `lib/services/server/`. Тесты: `test/server_client_test.dart`.
Сервер и админка: PR «Server: PostgreSQL catalog/profile API and admin panel».

## Статус

**Слой написан, но не подключён.** Ни один экран, провайдер или репозиторий
его не использует (это проверяет тест), ничего не запускается само (нет
таймеров и хуков запуска), каталог по-прежнему читается из локальной SQLite.
Подключение возможно только после согласования правил сбора данных (ниже).

## Что делает слой

| Возможность | Метод `CosmetixServer` | Нужно согласие |
|---|---|---|
| Каталог: страница, весь каталог, карточка товара | `fetchCatalogPage`, `fetchCatalog`, `fetchProduct` | нет (читает публичные данные, ничего о пользователе не отправляет) |
| Анонимный идентификатор устройства | `registerDevice` | `deviceRegistration` |
| События приложения | `sendEvents` | `usageEvents` |
| Профиль | `pushProfile(ProfileSyncPayload)` | `profile` |
| Реакции | `pushReaction`, `deleteReaction` | `reactions` |
| Отозвать согласие и удалить данные на сервере | `withdrawConsent`, `deleteServerData` | не нужно: удалять можно всегда |

Адрес и общий токен берутся из тех же настроек, что у ИИ-прокси (`AiConfig`):
это один сервер.

## Предлагаемые правила сбора данных (ждут согласования)

Все четыре согласия **выключены по умолчанию**, включаются отдельно и
отзываются в любой момент. Если правила изменятся, увеличивается
`ServerConsent.currentVersion`, и старое согласие перестаёт действовать.

**Уходит на сервер:**
* идентификатор: случайный id и токен, выданные сервером; без данных запроса;
* события (закрытый список из 4 типов): `app_open`, `screen_view` (имя экрана из
  фиксированного списка), `product_view` (id товара), `product_favorited`
  (id товара, да/нет);
* профиль: год рождения, тип кожи и «проблемы кожи» (только если введены в
  анкете, а не получены с участием анализа по фото);
* реакции: id товара, короткое название, тяжесть 1–5, дата.

**Не уходит никогда:** фотографии (лица, кожи, аватар, фото реакций),
результаты анализа лица и кожи (цветотип, подтон, тон, уверенность), имя, почта,
телефон, город, заметки к реакциям, тексты поиска и чата, названия товаров из
кошелька, постоянные идентификаторы устройства (IDFV, рекламный id, серийный
номер, MAC) и версия ОС или модель телефона.

## Надёжность

* Таймаут запроса 15 с. Повторы: GET, PUT и DELETE повторяются (до 3 попыток, пауза
  0,5 с → 1 с, потолок 8 с) при таймауте, обрыве сети и ответах 502/503/504.
* POST никогда не повторяется, если мог дойти до сервера: иначе устройство или
  события создались бы дважды.
* 429 ожидается по `Retry-After` (если не больше 8 с), иначе сразу
  `ServerRateLimited`. Остальные 4xx не повторяются.
* Редиректы не выполняются, токены не уходят на другой адрес. Ответ больше 5 МБ
  отклоняется.
* Ошибки: `ServerUnavailable`, `ServerTimeout`, `ServerRateLimited`,
  `ServerUnauthorized` (токен забыт сервером: локальные учётные данные
  сбрасываются), `ServerRejected`, `ServerBadResponse`, `ConsentRequired`,
  `DeviceNotRegistered`. Слой сам ничего не очередит и не хранит: оффлайн
  приложение работает как раньше, просто вызов завершается ошибкой.

## Что осталось на следующие шаги (после согласования)

Подробные рекомендации (с пометками, что проверено по источникам, а что нет):
`docs/server-client-recommendations.md`.

1. Экран согласий (четыре переключателя, ссылка «удалить мои данные»).
2. Очередь событий на случай оффлайна (локальная таблица, ограниченного размера).
3. Подмена источника каталога: сначала чтение с сервера с запасным вариантом в
   SQLite; id локальных и серверных товаров совпадают только для встроенного
   каталога (38 товаров), это нужно учесть.
4. Перенос токена устройства в Keychain (сейчас он в таблице `settings` SQLite
   внутри песочницы приложения, как токен ИИ-прокси).
