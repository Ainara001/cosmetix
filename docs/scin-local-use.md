## 3. Точный план шагов (после вашего «Да»)

### Шаг 0. Условия до скачивания
1. Свободное место: сейчас **8,8 ГиБ из 228 (занято 96 %)**. Нужно ≥ 5 ГиБ свободно после скачивания подмножества (1,55 ГиБ) и места для результатов. При нехватке: освободить место или выбрать меньшее подмножество.
2. Решение о папке (4.2): **вне репозитория и вне worktree** (папки `.claude/worktrees/…` могут удаляться вместе с сессией).

### Шаг 1. Выбор подмножества (только таблицы, уже скачаны)
`scin_select.py` (будет написан в `tools/eval/`): из `scin_cases.csv` и `scin_labels.csv` берёт случаи с `body_parts_head_or_neck = YES` и хотя бы одной дерматологической оценкой Фицпатрика;
пишет список путей `dataset/images/…`, число случаев и ожидаемый размер по листингу бакета. Ожидание по моим подсчётам: **649 случаев, 1 400 снимков, 1,55 ГиБ**. Если цифры не сойдутся, остановиться и проверить.

### Шаг 2. Скачивание
* По HTTPS из `storage.googleapis.com/dx-scin-public-data/<путь>`; `gsutil` и `gcloud` на машине нет (не нужны).
* Для каждого файла проверка размера и **MD5/CRC32C** из метаданных объекта (JSON API бакета отдаёт `md5Hash`); несовпадение, повторить и остановиться.
* Параллелизм небольшой, с паузами; без входа, без учётных данных.
* Каталог создаётся с правами `700` (доступ только владельцу).

### Шаг 3. Файл лицензии рядом с данными
`LICENSE_NOTICE.txt` в корне каталога данных: ссылка на SCIN Data Use License, указание на то, что данные **обработаны** (вычислены метрики; оригиналы не изменялись), перечень файлов-источников.

### Шаг 4. Анализ (E1–E3) локально
* Python-стенд `tools/eval` (MediaPipe локально, OpenCV локально, без сети). На время расчёта сеть не нужна.
* Вывод **только числа и идентификаторы случаев**: никаких картинок, миниатюр, контактных листов, наложений зон.
* Минимальный размер ячейки в таблицах результатов **5 случаев**: меньшие ячейки объединяются или не публикуются (риск повторной идентификации по редким сочетаниям).
* Точность измеряется интервалами Уилсона, малые группы помечаются «ненадёжно» (код `skin_eval.py` это уже делает при n < 30).

### Шаг 5. Результаты
Отчёт с таблицами в `docs/` (коммитятся только агрегированные числа), рядом ссылка на лицензию и пометка «данные SCIN обработаны». Снимки и промежуточные файлы в git не попадают.

### Шаг 6. Удаление
После отчёта: удалить каталог со снимками, если не нужен для повторных расчётов; если нужен, записать дату пересмотра (не позже 30 дней) и причину. Метаданные CSV не содержат снимков и могут остаться.

## 4. Защита данных

### 4.1. Правило для ИИ-ассистента

Просмотр изображения ассистентом (инструмент чтения картинок) это **передача изображения модели третьей стороны**. Поэтому в сессиях с ИИ-ассистентом
**снимки SCIN не открываются и не просматриваются**; скрипты выдают числа, а не картинки. (В ходе аудита PR #24 я просматривал только публичные фото Wikimedia Commons с
открытой лицензией, не SCIN.) Проверка «глазами» результатов E1 для SCIN, если понадобится, делается человеком самостоятельно, не в чате.

### 4.2. Хранение

| Мера | Состояние / решение |
|---|---|
| Диск зашифрован | **FileVault включён** (проверено `fdesetup status`) |
| Резервные копии | Time Machine: **назначений не настроено** (`tmutil destinationinfo`), копий на внешних носителях нет; в iCloud не выгружать |
| Место | вне репозитория и worktree, например `~/cosmetix-eval-data/scin.noindex/` (суффикс `.noindex` исключает папку из Spotlight; **работу этого приёма проверить `mdfind` после создания, не проверено**) |
| Права | `chmod 700` на каталог |
| Копирование | не копировать в репозиторий, облако, мессенджеры, артефакты, не прикладывать к PR и чатам; не читать инструментами, которые отправляют содержимое наружу |
| Идентификаторы | в журналах и отчётах только `case_id`; пути к файлам и EXIF не публиковать |
| Запрещено | любое сопоставление лиц между снимками, векторы лиц, поиск изображений в сети, использование метаданных для установления личности (**повторная идентификация запрещена лицензией**) |
| Что допустимо | детектор лица и точки (определение, есть ли лицо и где зоны), это не распознавание личности |

### 4.3. Если снимок всё же попал наружу
Прекратить, записать что и куда (дата, сервис), удалить где возможно, сообщить владельцу; повторно не использовать этот канал.

## 5. Передача третьей стороне (Gemini): условия, пока не выполнены

Фото SCIN в Gemini **не отправляются**, пока не выполнено всё:

1. **Режим ключа.** Бесплатная квота: Google использует присланное, его могут читать люди, прямой запрет «Do not submit sensitive, confidential, or personal information to the Unpaid Services»
   ([условия](https://ai.google.dev/gemini-api/terms), версия «Effective March 23, 2026», прочитано 5 ноября 2026). Снимки кожных заболеваний людей это чувствительные данные.
   Нужен **платный** Cloud-проект (Google не использует запросы для улучшения продуктов; запросы журналируются ограниченное время для выявления нарушений).
2. **Медицинское ограничение условий Gemini:** нельзя использовать сервис «in clinical practice, to provide medical advice» и в способе, требующем одобрения как медицинское изделие.
   Научное сравнение тона кожи не клиническая практика, но формулировку нужно сверить с юристом.
3. **Лицензия SCIN** допускает передачу («Share») при соблюдении условий, но права на приватность не лицензируются: вопрос, можно ли отправлять эти снимки внешнему ИИ, это решение юриста, а не вывод из текста.
4. **Ваше явное разрешение** на конкретное подмножество и режим.

Если всё выполнено: сравнение Gemini с врачом по Фицпатрику на тех же 649 случаях (~1 400 вызовов, суточный лимит токенов прокси 200 000 нужно учесть или поднять осознанно).
