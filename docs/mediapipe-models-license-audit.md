# MediaPipe: происхождение и лицензии файлов моделей в `mediapipe_face_mesh` 3.2.2

Дата: 5 ноября 2026 (дополнено сверкой контрольных сумм). Относится к PR #22 (Real Skin Makeup, этап 1).
Обозначения: ✓ прочитано в первоисточнике; ✱ подтверждено частично или косвенно; ✗ не подтверждено.

## 1. Какие файлы модели попадают в приложение

Пакет объявляет в `pubspec.yaml` весь каталог `assets/models/`, поэтому в сборку iOS попадают **все 8 файлов** (проверено: они лежат в
`Runner.app/Frameworks/App.framework/flutter_assets/packages/mediapipe_face_mesh/assets/models/`). Общий размер около 11,9 МБ.

| Файл в пакете | Что это (по описанию пакета) | Размер, байт | Используется нами | Карточка модели (Google) и её надпись о лицензии |
|---|---|---|---|---|
| `face_detection_short_range.tflite` | BlazeFace, детектор лица, короткая дистанция | 229 032 | **да** | «BlazeFace Model Card (Short Range)», 9 июня 2021, «LICENSED UNDER Apache License, Version 2.0» ✓ |
| `face_mesh_v2.tflite` | FaceMesh V2, 478 точек (в Google опубликована как `face_landmarks_detector.tflite` внутри `face_landmarker.task`) | 2 553 590 | **да** | «Model Card MediaPipe Face Mesh V2», 15 сентября 2022, «Apache License, Version 2.0» ✓ |
| `face_detection_full_range.tflite` | BlazeFace, дальняя дистанция | 1 083 786 | нет | карточка «Full Range», 19 января 2021, Apache 2.0 ✓ |
| `face_detection_full_range_sparse.tflite` | BlazeFace, дальняя, «разреженный» | 676 746 | нет | карточка «Sparse (Full Range)», 31 марта 2021, Apache 2.0 ✓ |
| `face_blendshapes.tflite` | 52 blendshape-коэффициента | 955 312 | нет | «Blendshape V2», 11 ноября 2022, Apache 2.0 ✓ |
| `face_landmark_with_attention.tflite` | Attention Mesh, 478 точек | 2 495 952 | нет | «Attention Mesh», 28 августа 2020, Apache 2.0 ✓ |
| `iris_landmark.tflite` | модель радужки | 2 640 568 | нет | «MediaPipe Iris», Apache 2.0 ✓ |
| `mediapipe_face_mesh.tflite` | FaceMesh V1, 468 точек (в пакете переименована из `face_landmark.tflite`) | 1 242 398 | нет | карточка по ссылкам из `models.md` ведёт на PDF в Google Drive, не открылась ✗ |

**Какие модели реально загружаются.** В `mediapipe_landmark_provider.dart` вызываются `FaceDetectorProcessor.create(maxResults: …)` и
`FaceMeshProcessor.create()` без выбора моделей. По исходникам пакета значения по умолчанию: детектор `FaceDetectionModel.shortRange`,
сетка `FaceMeshModel.v2`, радужка выключена (`enableIris = false`), blendshape-процессор не создаётся. Значит, **используются два файла**
(суммарно 2 782 622 байт); остальные **шесть** лежат в приложении без дела (9 094 762 байт, около 8,7 МиБ).
Интеграционный тест с настоящим MediaPipe на симуляторе подтверждает, что с этими двумя моделями находится 478 точек.

## 2. Лицензии кода и весов отдельно

| Часть | Лицензия | Подтверждение |
|---|---|---|
| Dart/нативный код пакета `mediapipe_face_mesh` | BSD-3-Clause | `LICENSE` пакета ✓ |
| `ffi` (зависимость пакета) | BSD-3-Clause | `LICENSE` пакета ✓ |
| Код MediaPipe (репозиторий Google) | Apache 2.0 | `LICENSE` репозитория прочитан ✓ |
| TensorFlow Lite C (в пакете пересобран) | Apache 2.0, внутри статически слинкованы XNNPACK, FlatBuffers, Abseil, ruy, gemmlowp, pthreadpool, cpuinfo, FP16, farmhash, fft2d и **Eigen (MPL-2.0 с BSD-частями)** | `THIRD_PARTY_NOTICES.md` пакета; то, что TFLite пересобран, пакет заявляет сам ✱ |
| **Файлы весов (модели)** | **Apache 2.0, как указано в карточке каждой модели** (см. таблицу выше) | карточки Google прочитаны для 7 из 8 файлов ✓; для FaceMesh V1 ✗ |

Важно: лицензия репозитория MediaPipe и лицензия пакета-обёртки сами по себе **не** дают прав на веса. Права на веса здесь основаны на
надписи «LICENSED UNDER Apache License, Version 2.0» в карточках самих моделей, которые Google публикует рядом с моделями.
Файлов `.tflite` **нет** в репозитории MediaPipe (проверено через API GitHub: ни в `modules/face_detection`, ни в `modules/face_landmark`),
они скачиваются с `storage.googleapis.com`; страницы документации Google (`face_detector`, `face_landmarker`) отдельных условий не называют.

## 3. Коммерческое использование и распространение в приложениях

- Apache 2.0 разрешает коммерческое использование, изменение и распространение, в том числе внутри мобильных приложений, при условии
  выполнения раздела 4: приложить текст лицензии и сохранить уведомления об авторстве, отметить изменения. Это условие **сейчас не выполнено на стороне
  приложения**: в Cosmetix нет экрана «Лицензии» (поиск `showLicensePage` и `LicenseRegistry` в `lib/` ничего не нашёл). Пакет, по его
  заявлению, кладёт уведомления в файл `NOTICES`, который читает сборщик лицензий Flutter, но я это не проверял запуском.
- Карточки описывают назначение моделей (AR-развлечения, одно лицо крупным планом, камера смартфона) и исключают распознавание личности
  и слежку. Это **не лицензионное ограничение**, но наше использование (примерка макияжа на одном фото) в эти рамки укладывается, а
  идентификация и распознавание лиц в модуле не делается.
- Это моё чтение условий, а не юридическое заключение; правила магазинов приложений я не проверял.

## 4. Можно ли исключить шесть неиспользуемых моделей

Код пакета запрашивает файл модели только по ключу при создании процессора (`_materializeMeshModel`, `_materializeDetectorModel`,
`_materializeIrisModel`, `_materializeBlendshapesModel`), поэтому отсутствие неиспользуемых файлов не должно мешать нашим двум вызовам.
Это **не проверено запуском**. Штатного способа исключить ассеты зависимости настройками самого приложения я не нашёл. Практичный путь:
локальная копия пакета (`path`-зависимость) без шести файлов и с сохранёнными `LICENSE`, `NOTICES`, `THIRD_PARTY_NOTICES.md`,
плюс запуск интеграционного теста на такой сборке. Эффект: минус около 8,7 МиБ и исчезает вопрос по FaceMesh V1.
В этом PR изменение не делалось, это решение владельца.

## 5. Что остаётся неподтверждённым (вопросы к юристу или к следующей проверке)

1. ~~Идентичность файлов~~ **закрыто для двух используемых моделей**: побайтно совпадают с официальными файлами Google (раздел 8).
   Для остальных шести файлов сверка не делалась, кроме `face_blendshapes.tflite` (совпал).
2. Карточка FaceMesh V1 (`mediapipe_face_mesh.tflite`) не прочитана. Пока файл в сборке, права на него не подтверждены.
3. Данные обучения: карточки говорят о согласованных изображениях, права на данные карточка не раскрывает. Это обычный остаточный вопрос для любых предобученных весов.
4. Надпись в карточке имеет юридический вес ниже, чем отдельный файл лицензии на веса. Прямого заявления Google «веса можно использовать в коммерческих приложениях» на страницах документации я не нашёл.
5. Пересобранный TensorFlow Lite с MediaPipe-операторами и вложенные компоненты (Eigen MPL-2.0, fft2d «freely distributable») требуют общей юридической проверки состава перед публикацией.
6. Экран лицензий (в приложении его нет, раздел 9) и текст политики конфиденциальности: фото обрабатывается на устройстве, но признаки лица могут считаться биометрическими данными в ряде юрисдикций. Это вопрос к юристу.
7. Товарные знаки «MediaPipe» и «TensorFlow» принадлежат Google; в интерфейсе и маркетинге их нельзя использовать как название продукта.

## 6. Альтернативы (на случай, если права подтвердить не удастся)

Сейчас замена **не требуется**: для двух используемых моделей Google указывает Apache 2.0. Если юрист не примет такую основу, кандидаты (условия
**не проверялись**, только названы):
- Apple Vision `VNDetectFaceLandmarksRequest` на iOS (системный компонент, без своих весов; точек меньше, чем 478, зоны придётся пересчитывать);
- Google ML Kit Face Mesh Detection (по описанию 468 точек, на устройстве, указан как бета; условия ML Kit нужно читать отдельно);
- собственная или лицензированная модель с явным файлом лицензии на веса.
Смена источника точек затрагивает один файл (`mediapipe_landmark_provider.dart`) благодаря интерфейсу `FaceLandmarkProvider`.

## 7. Вывод (первоначальный, до сверки сумм; актуальный вывод в разделе 10)

- **Две используемые модели:** права подтверждены надписями Apache 2.0 в карточках Google (первоисточник прочитан), но байтовая идентичность и юридическое заключение остаются открытыми.

- До выполнения пунктов 1–2 из раздела 5 и добавления экрана лицензий **сборку не распространять** (TestFlight, друзьям, магазины). Запуск на вашем собственном телефоне для разработки распространением не считается.

## 9. Видны ли лицензии пользователю

- **Данные есть.** В собранном приложении лежит `flutter_assets/NOTICES.Z` (108 КБ, в распакованном виде около 1,4 МБ); в нём есть запись
  `mediapipe_face_mesh` с уведомлениями об Apache-2.0 для TensorFlow Lite и MediaPipe (найдено в собранном iOS-приложении).
- **Экрана нет.** В `lib/` нет `showLicensePage`, `LicensePage`, `LicenseRegistry`, `showAboutDialog`, `AboutListTile` и строк «Лицензии»
  ни в интерфейсе, ни в переводах (поиск по коду и по файлам переводов EN/KK). Пользователь эти уведомления в приложении **увидеть не может**.
  Единственная лицензионная ссылка в приложении: подпись OpenStreetMap на карте магазинов.
- Для коммерческого выпуска нужен экран лицензий (самый простой путь: стандартный `showLicensePage` в «Настройках»). В PR он не добавлялся:
  это новая функция вне согласованного объёма.

## 10. Актуальный вывод и вопрос шести неиспользуемых моделей

- **Используемые две модели:** происхождение подтверждено побайтно (раздел 8), лицензия Apache 2.0 указана в карточках Google (раздел 1).
- **Шесть неиспользуемых файлов** (`face_detection_full_range`, `face_detection_full_range_sparse`, `face_blendshapes`, `face_landmark_with_attention`,
  `iris_landmark`, `mediapipe_face_mesh`) всё равно попадают в приложение. Для **коммерческого выпуска нужно одно из двух**:
  1. удалить их из сборки (локальная копия пакета без этих файлов; проверить запуском, раздел 4); либо
  2. подтвердить условия распространения всех восьми файлов, то есть прочитать карточку FaceMesh V1, сверить остальные файлы с официальными и получить юридическое заключение.
  Рекомендуется вариант 1: он убирает около 8,7 МиБ и сам вопрос.
- **Статус функции:** внутренний прототип. Сборки за пределы вашего компьютера не передавать, пока не закрыты пункты выше, экран лицензий и юридическая проверка.
